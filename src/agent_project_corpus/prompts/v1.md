# Project creation/mutation corpus — prompt v1

Versioned: a prompt change is a model change.

---

You produce **training examples for the agent that builds and changes Pipelines** — the main
product agent. It is a **tool-calling** agent, so an example is a **trajectory**, not an answer.

## The shape

```json
{"example_id":"kebab-slug","kind":"create|mutate",
 "profile":{"industry":"...","persona":{"role":"...","constraints":["..."]},
            "connections":[{"name":"...","state":"captured|discovered"}],
            "tables":[{"database":"...","name":"...","rows":250000,
                       "columns":[{"name":"...","type":"...","null_fraction":0.11}]}]},
 "intent":"what the user asked, in their words",
 "before":null,
 "trajectory":[
   {"call":"list_datasets","args":{},"observation":"…what came back…"},
   {"call":"get_dataset","args":{"dataset":"crm.accounts"},
    "observation":"…columns, null rates…","because":"list_datasets named it as the candidate"},
   {"call":"clean","args":{"drop_null":"sfdc_account_id","as_of":"event_updated_datetime_pt"},
    "because":"get_dataset reported 11.4% null ids and a load-date timestamp"}],
 "reply":"what the agent says to the user",
 "pipeline":{"connect":true,"clean":true,"point_in_time":true,"leakage_free":true,
             "model":true,"model_kind":"gbdt","calibrated":true,"holdout":true,
             "explain":"shap","serve":true,"act":true}}
```

## Every call after the first needs a `because`, and it must name an observation

*"because list_datasets named it as the candidate"* · *"because get_dataset reported 11.4% null
ids"*. If a call's justification is the user's ask rather than something a previous call returned,
it is a scripted step and teaches nothing.

**The test:** could this pipeline be produced without the observations? If yes, rewrite it so the
schema decides something. Change one fact in the profile — remove the label column, drop the null
rate, remove the cutoff — and the correct trajectory must change.

## Half your examples must be MUTATIONS

`kind: "mutate"` carries a `before` pipeline and changes it. **What must not change is as much of
the lesson as what must** — a mutation that silently rebuilds from scratch has lost the user's
work.

Real mutation asks: *"add calibration to that"* · *"actually use the last 90 days"* · *"drop the
null accounts"* · *"that ran too long"* · *"no, base it on the other table"*. Some of them
invalidate downstream steps, and the reply should say so.

## The pipeline must match its methodology

Churn: point-in-time, leakage-free, **calibrated**, holdout, SHAP. Forecast: temporal validation
and backtest, **never calibrated** — there is no probability to calibrate. Anomaly: unsupervised,
threshold-governed, no label. Retrieval: indexed and grounded, no supervised label at all.

Getting this wrong teaches the neighbouring solution, which is the defect that made one pipeline
shape serve churn, lead scoring and collections alike.

## Also teach the refusals

An agent that always builds will build something worthless. Include examples where the right move
is to **ask one clarifying question** (the ask is ambiguous), or to **decline** — and get the reason
right: *discovered but not captured* is answered **"capture it first"**, not "cannot be done".

## Diversity

Every example should surprise someone who read the last one. If you produce a structure you have
produced before, pick something further away.
