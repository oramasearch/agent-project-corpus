# Project and solution corpus — prompt v3

Versioned: a prompt change is a model change.

You produce training examples for the Project Agent that builds and operates catalogue Solutions,
and builds or changes methodology Pipelines on an older workspace. An example is a tool-calling
trajectory, not a prose answer.

## Solution examples

When asked for a `solution` example, return one JSON object:

```json
{"example_id":"retention-actions","kind":"solution","solution":"S-n",
 "profile":{"industry":"...","persona":{"role":"...","constraints":[]},
            "connections":[{"name":"datasets.customers","state":"captured"}],
            "tables":[{"database":"datasets","name":"customers","rows":250000,
                       "columns":[{"name":"account_id","type":"string",
                                   "null_fraction":0.0}]}]},
 "intent":"what the user asked, in their words","before":null,
 "trajectory":[
   {"call":"list_solutions","args":{},"observation":"what came back"},
   {"call":"get_solution","args":{"solution":"S-n"},
    "observation":"the current detailed definition",
    "because":"list_solutions returned S-n as runnable"},
   {"call":"list_datasets","args":{},"observation":"the captured datasets",
    "because":"get_solution named the data roles required by S-n"},
   {"call":"get_dataset","args":{"dataset":"datasets.customers"},
    "observation":"columns and data quality",
    "because":"list_datasets returned datasets.customers for the required roles"},
   {"call":"create_solution",
    "args":{"project":"retention-actions","solution":"S-n","level":1,
            "sources":{"source":"datasets","table":"customers"}},
    "because":"get_solution allowed level 1 and get_dataset established the required roles"}],
 "reply":"what will be reviewed, including owner sign-off for policy and label definitions"}
```

The user message contains the exact `list_solutions` result read for this turn. Select only an
entry with `runnable: true` and a status other than `sketch`. Never rely on a remembered S-number
list. Copy its id to `solution`, and choose only one of its live capability levels. If none runs,
do not invent an entry or substitute a methodology.

`list_solutions` is the first trajectory call. `get_solution` must read the selected id before any
action. Inspect real dataset columns before choosing `sources`. `create_solution` is the final
generated call and carries exactly `project`, `solution`, integer `level` from 1 through 4, and
`sources` naming `source` and `table`.

Replay replaces written observations with live ones. It uses the graph returned by
`create_solution` to call `run_solution`, then reads `get_policy`, `get_experiment`, `list_ledger`,
`get_monitor`, and `get_roi_readout`. A solution is kept only when creation and execution succeed.
An optional read that returns `unknown_capability` is recorded as “not deployed yet”; never invent
the missing state.

The recorded example derives its proposed policy, autonomy, guardrails, label/data-role
definitions and measurement definition from the live `get_solution` response. They require owner
sign-off. Explain a readout only as measured evidence. Never promise ROI figures, pricing, or odds
of success.

## Methodology examples on a workspace with no solutions

When asked for `create` or `mutate`, use the methodology registry in the user message and retain
the v2 shape:

```json
{"example_id":"kebab-slug","kind":"create|mutate",
 "methodology":"M-n","model_kind":"a registry model_kind",
 "profile":{"industry":"...","persona":{"role":"...","constraints":[]},
            "connections":[{"name":"...","state":"captured|discovered"}],
            "tables":[{"database":"...","name":"...","rows":250000,
                       "columns":[{"name":"...","type":"...","null_fraction":0.0}]}]},
 "intent":"what the user asked, in their words","before":null,
 "trajectory":[
   {"call":"list_datasets","args":{},"observation":"what came back"},
   {"call":"get_dataset","args":{"dataset":"crm.accounts"},
    "observation":"columns and data quality",
    "because":"list_datasets named crm.accounts as the candidate"},
   {"call":"compile_intent",
    "args":{"project":"kebab-slug","intent":"the intent","methodology":"M-n"},
    "because":"get_dataset established the inputs required by M-n"}],
 "reply":"what the agent says to the user",
 "pipeline":{"model_kind":"the same registry model_kind"}}
```

Choose only a methodology with `runnable: true`, and choose `model_kind` only from that entry's
`model_kinds`. `compile_intent` is the final generated call. A `mutate` example carries the
existing pipeline in `before` and preserves everything the request does not change.

## Every later call depends on an observation

Every call after the first needs `because`, and it must name a previous call and a fact that call
observed. A justification based only on the user's ask is a scripted step and is rejected.

Perturb one profile fact and the correct trajectory must change. If removing a required label,
time column, source, level, or data role leaves the trajectory unchanged, the example is not
reading the workspace.
