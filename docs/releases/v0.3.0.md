# agent-project-corpus v0.3.0

**Released 2026-11-16. A minor release.** Since [v0.2.0](v0.2.0.md): the licence, the security policy, base images pinned by digest and the public-tree cleanup (placeholder ids in the replayed example). Image: `docker.io/oramasearch/agent-project-corpus:v0.3.0`, not published (see *Known issues*).

This release is the tree of `dev` with these notes and the version.

### The public-tree cleanup — #27

Nothing internal is left in the files that will be published: `.public-exclude` was added and then removed again once the agent files were rewritten to ship publicly; the corpus card is MIT and no longer marked internal; in `corpus/project-sft-v1.jsonl` row 23 the 37 distinct node ids became consistent placeholders (`00000000-0000-4000-8000-<n>`); the read-only refusal a user sees no longer carries a tracker link; the package author is `Orama Search Inc.`.

### The licence — #26

Everything in this repository that Orama wrote is under the MIT licence. Contributors sign `CLA.md` once. `THIRD_PARTY_LICENSES` lists every runtime dependency with its licence text; none is incompatible with MIT distribution.

## Known issues

Security-relevant first. All open at this tag.

1. #8 (security): a Lake turn's replay calls write actions (`compile_intent`, `run`, `create_solution`, `run_solution`) the task credential does not grant. Lake turns are refused until the sandbox workspace exists, as in v0.2.0.
2. #28 (release blocker for publishing): the image is built on `python:3.12-slim`, which bundles GPL and LGPL userland, so **the image is not published**. It is built and kept in the project's non-public Docker Hub repository until it moves to a scratch base with static binaries.
3. #6: the task's workspace is not passed explicitly on data-plane calls. Lake scopes the task credential to the task's workspace.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes run the operator's default image of this agent; the changes since v0.2.0 are proven by the test suite only. Moving a Lake to `:v0.3.0` is a separate operator change.
