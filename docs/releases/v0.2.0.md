# agent-project-corpus v0.2.0

**Released 2026-10-25. A minor release.** The fixes from the 2026-10-21 security review, and one
behaviour change: **a Lake turn is now refused before it starts** (below). Image:
`docker.io/oramasearch/agent-project-corpus:v0.2.0`.

## Behaviour change: Lake turns are refused until the sandbox

**In Lake, this agent records no example in v0.2.0.** Every turn that comes from Lake is refused
before the model runs, with a reply that says why. No model tokens are spent and
nothing is read or written in the person's workspace.

Why: every example is replayed through write actions (`compile_intent` and `run`, or
`create_solution` and `run_solution`). Lake grants this agent's task credential only
`workspace_query`, `workspace_openapi` and `get_agent_task`, and Lake's catalogue says the agent
changes nothing. In v0.1.0 a Lake turn spent the person's model tokens and then failed at replay;
with a wider grant it would have created and run a project in their workspace.

The project chose, on 2026-10-25, to replay examples in a **sandbox workspace**. Lake turns come back when that
lands and the agent replays there. The batch command line, run with an owner token, still replays
and records examples as before.

## What changed since v0.1.0

Every pull request merged into `dev` since the tag `v0.1.0`:

| PR | Change |
|---|---|
| #16 | A Lake turn changes nothing in the person's workspace: `Node(read_only=True)` raises `NodeError("read_only")` on any action without sending it, the node a Lake turn builds is read-only, and `run_turn` refuses such a turn before the model runs |
| #15 | A turn's credential goes only to Lake at this service's `LAKE_URL`: the turn's `lake_url` is ignored, and `zetta_base_url` is accepted only on `LAKE_URL`'s origin and under its path, with no user info, query, fragment or dot segments. Anything else is refused before any request |
| #14 | The service token is compared in constant time (`hmac.compare_digest`), and `POST /v1/turn` **fails closed**: with `AGENT_SERVICE_TOKEN` unset or empty every turn is refused with 503 |
| #12 | Records the v0.1.0 image digest in the v0.1.0 notes |

### Settings it needs

| Variable | v0.1.0 | v0.2.0 |
|---|---|---|
| `AGENT_SERVICE_TOKEN` | Checked when set; the route was open when unset | **Required.** Unset or empty refuses every turn with 503 |
| `LAKE_URL` | The fallback model gateway address | **Required for every turn.** The only model gateway address, and the origin and path a turn's `zetta_base_url` must be under. Unset refuses every turn that would send a credential |

The operator already renders `AGENT_SERVICE_TOKEN`, `LAKE_URL` and `AGENT_MODEL` on every library
agent pod, and Lake sends its internal address (the same as `LAKE_URL`) as the workspace route, so
no operator change has to roll first. A service run by hand needs both variables set.

## What it does not include

Unchanged from [v0.1.0](v0.1.0.md#what-it-does-not-include), plus:

- **Recording an example from Lake.** Refused until the sandbox workspace.
- **Training.** Nothing has been trained on the corpus.
- **A corpus to train on.** The committed 23 examples are unchanged and predate prompt v3 and
  replay.
- **An offline evaluation**, multi-turn trajectories, and usage reporting of its own.

## Known issues

Security-relevant first. All open at this tag.

1. **Workspace identity is not passed explicitly**. Bus calls send no
   `workspace_id` and rely on the task credential to choose the workspace, and an idle agent
   long-polls continuously instead of backing off.
2. **Lake turns are refused** until the agent replays in a sandbox workspace. This is the behaviour change
   above; #8 stays open until the sandbox replay works.
3. **The lease is kept by activity only.** The agent sends no heartbeat; Lake renews a claim's
   lease on every accepted event and every capability call made with the task credential. Not
   observed to expire.
4. **The bus restarts from sequence 1** on every process start. Lake filters already-claimed tasks
   and losing claims are skipped.
5. **The committed corpus predates prompt v3 and replay**. 22 of its 23 examples carry
   observations the model wrote.

Fixed in this release: #13 (token
timing and the open route) and #9
(the caller-chosen destinations), both v0.1.0 known issue 3.

## Where it has run

**The v0.2.0 tree had not run on a development environment when it was released.** Every Lake took
the operator's default library image, `oramasearch/agent-project-corpus:v0.1.0` (orama-operator
`internal/controller/lake_defaults.go`). Moving to `:v0.2.0` is a separate operator change.
