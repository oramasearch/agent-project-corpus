# Project creation/mutation corpus — prompt v2

Versioned: a prompt change is a model change.

You produce training examples for the agent that builds and changes Pipelines. An example is a
tool-calling trajectory, not a prose answer.

## Required shape

Return one JSON object:

```json
{"example_id":"kebab-slug","kind":"create|mutate",
 "methodology":"M-n","model_kind":"a registry model_kind",
 "profile":{"industry":"...","persona":{"role":"...","constraints":[]},
            "connections":[{"name":"...","state":"captured|discovered"}],
            "tables":[{"database":"...","name":"...","rows":250000,
                       "columns":[{"name":"...","type":"...","null_fraction":0.0}]}]},
 "intent":"what the user asked, in their words","before":null,
 "trajectory":[
   {"call":"list_datasets","args":{},"observation":"what came back"},
   {"call":"get_dataset","args":{"dataset":"crm.accounts"},
    "observation":"columns and data quality",
    "because":"list_datasets named crm.accounts as the candidate"},
   {"call":"compile_intent",
    "args":{"project":"kebab-slug","intent":"the intent","methodology":"M-n"},
    "because":"get_dataset established the inputs required by M-n"}],
 "reply":"what the agent says to the user",
 "pipeline":{"model_kind":"the same registry model_kind"}}
```

## The registry is authoritative

The user message contains `list_methodologies` output read for this turn. Choose only an entry with
`runnable: true`. Copy its `id` to `methodology`, choose `model_kind` only from that entry's
`model_kinds`, and use the same value in `pipeline.model_kind`.

Do not rely on a remembered methodology list. Do not substitute a nearby runnable methodology for
the requested one. If the request needs an entry with `runnable: false`, name that methodology and
its `issue` in the reply instead of pretending another pipeline solves it.

`compile_intent` must be the final trajectory call. It must carry `project`, the example's `intent`,
and the example's `methodology`. The engine response replaces any imagined pipeline shape during
replay, so do not invent methodology-specific steps in `pipeline`. Replay runs that compiled graph
and records the trainer response after the generated trajectory.

## Every later call depends on an observation

Every call after the first needs `because`, and it must name a previous call and a fact that call
observed. A justification based only on the user's ask is a scripted step and is rejected.

Perturb one profile fact and the correct trajectory must change. If removing a label, time column,
or null rate leaves the trajectory unchanged, the example is not reading the data.

## Mutations

A `mutate` example carries the existing pipeline in `before`. Change only what the request and
observations require. Preserve everything else.

## Refusals

Ask one clarifying question when the request is ambiguous. A discovered but uncaptured connection
is answered with "capture it first". Never record an example for a methodology the registry says is
not runnable.
